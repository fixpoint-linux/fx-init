# scripts/kernel-pin.txt — the M4 image increment's pinned kernel input.
#
# DESIGN.md §8.5 decision for v1 (REVISED, was "take the HOST kernel"):
# the image takes its kernel from a PINNED, FETCHABLE artifact — the
# openSUSE kernel-default-base RPM below, downloaded + sha256-verified by
# scripts/fetch-kernel.sh.  The host's /boot and /usr/lib/modules are NO
# LONGER inputs: the image is reproducible on any machine that can reach
# the URL (nothing about the kernel depends on the build host anymore).
#
# KNOWN LIMITATION (honest): openSUSE Tumbleweed PRUNES old packages from
# download.opensuse.org — 7.1.8-1.1 (this host's kernel, the pre-revision
# pin) is ALREADY GONE, so this URL WILL eventually 404 and the pin will
# need moving to whatever current build carries the config facts below.
# The DURABLE fix is to host a trimmed artifact (~19 MB: vmlinuz + the 4
# modules + config) as a release asset in a fixpoint-linux repo and pin
# THAT URL instead — flagged as the follow-up increment, not done here.
#
# Keys consumed by scripts/fetch-kernel.sh + tests/mkinitramfs.sh:
#   url             the RPM to download (cache dir: $FX_KERNEL_CACHE,
#                   default .kernel-cache/, gitignored)
#   rpm_sha256      pin of the whole RPM (a cached copy failing this hash
#                   is re-fetched, never trusted)
#   rpm_size        early sanity check before the hash
#   kernel_version  the /usr/lib/modules/<version> tree name in the RPM;
#                   the image's /lib/modules/<version> dir — the single
#                   place the version string lives
#   vmlinuz_path    vmlinuz, relative to the RPM root
#   vmlinuz_sha256  pin of the EXTRACTED vmlinuz (tests/qemu_*.sh verify
#                   this after the fetch: a mismatch FAILS the harness)
#   config_path     the kernel's own config, kept for future assertions
#   module          one disk-path module per line, relative to
#                   /usr/lib/modules/<kernel_version>/ in the RPM.
#                   MEASURED on 7.2.7: the set is FIVE modules — this
#                   RPM's ext4.ko has 10 UNDEFINED mb_cache_* symbols
#                   (readelf) resolved by kernel/fs/mbcache.ko.zst in the
#                   same RPM (the 7.1.8 module set also carried it).
#                   insmod order is zig/src/init.zig's DISK_MODULE_ORDER:
#                   crc16 mbcache jbd2 ext4 virtio_blk.
#
# Kernel config facts this increment depends on (all =y, MEASURED from
# this RPM's own config file):
#   CONFIG_BLK_DEV_INITRD, CONFIG_RD_GZIP (gzip'd newc cpio initrd),
#   CONFIG_DEVTMPFS + CONFIG_DEVTMPFS_MOUNT (devtmpfs; note the automount
#   only applies to a real rootfs — an initramfs PID1 mounts it itself),
#   CONFIG_SERIAL_8250_CONSOLE (console=ttyS0), CONFIG_TMPFS,
#   CONFIG_VIRTIO, CONFIG_VIRTIO_PCI, CONFIG_VIRTIO_CONSOLE.
#   Only VIRTIO_BLK / EXT4 / JBD2 / CRC16 are =m (the module list below).
