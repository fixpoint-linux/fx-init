# scripts/kernel-pin.txt — the pinned kernel input (M5 increment).
#
# DESIGN.md §8.5 decision for v1 (carried through M4 and now M5): the
# image takes its kernel from a PINNED, FETCHABLE artifact — a TRIMMED
# TARBALL hosted as a release asset in THIS repo, downloaded +
# sha256-verified by scripts/fetch-kernel.sh.  Nothing about the kernel
# depends on the build host.
#
# PROVENANCE (M5, supersedes the openSUSE RPM cut): linux-6.12.19 LTS
# from kernel.org (tarball d73bf057bec04434b169d1b61641936f7d0c97ceb923a281f32e35dd4dcc6531),
# built in a debian:stable container (gcc 14.2, flex/bison/bc/libelf/libssl)
# from a `make tinyconfig` base + the image fragment (BLK_DEV_INITRD,
# RD_GZIP, DEVTMPFS(+MOUNT), TMPFS, SERIAL_8250_CONSOLE, VIRTIO*,
# EXT4_FS... plus the hidden gates tinyconfig leaves off: VIRTIO_MENU,
# TTY, PRINTK — and two M5 discoveries: FILE_LOCKING, without which
# dl_open's F_SETLK fails EACCES and the boot dies before a verdict, and
# the CRYPTO chain =y, without which jbd2.ko fails to insmod).  This
# first M5 artifact is the BELT build: the five disk-path modules below
# are =m exactly as the M4 mechanism ships them; the zero-module build
# (=y everywhere, no modules tree) supersedes it in the next step.
# Repacked deterministically (tar --sort=name, owner/group/mtime 0,
# gzip -n).
#
# HONEST RISK (unchanged): a GitHub release asset CAN be replaced or
# deleted by anyone with repo admin — the same trust domain as this
# repo's code.  The pin's tar_sha256 makes replacement LOUD, not
# impossible: a swapped asset fails the hash check (and a deleted one
# 404s) and fetch-kernel exits non-zero.  There is no fallback.
#
# Keys consumed by scripts/fetch-kernel.sh + tests/mkinitramfs.sh:
#   url             the release asset to download (cache dir:
#                   $FX_KERNEL_CACHE, default .kernel-cache/, gitignored)
#   tar_sha256      pin of the whole tarball (a cached copy failing this
#                   hash is re-fetched, never trusted)
#   tar_size        early sanity check before the hash
#   kernel_version  the /lib/modules/<version> tree name; the image's
#                   /lib/modules/<version> dir — the single place the
#                   version string lives
#   vmlinuz_path    vmlinuz, relative to the tarball root (top level)
#   vmlinuz_sha256  pin of the EXTRACTED vmlinuz (verified after the
#                   unpack AND by tests/qemu_*.sh: a mismatch FAILS)
#   config_path     the kernel's own config, relative to the tarball root
#                   (kept for future config assertions)
#   module          one disk-path module per line, relative to the
#                   tarball's modules/ tree (6.12 in-tree paths: note
#                   crc16 lives at lib/crc16.ko and mbcache at
#                   fs/mbcache.ko in this tree, unlike the RPM's
#                   kernel/lib/crc/... layout).  insmod order is
#                   zig/src/init.zig's DISK_MODULE_ORDER:
#                   crc16 mbcache jbd2 ext4 virtio_blk.
#
# Kernel config facts this increment depends on (all =y in the shipped
# config): BLK_DEV_INITRD, RD_GZIP, DEVTMPFS(+MOUNT), TMPFS,
# SERIAL_8250_CONSOLE, VIRTIO, VIRTIO_PCI, VIRTIO_CONSOLE, PRINTK,
# FILE_LOCKING.  =m: VIRTIO_BLK, EXT4_FS (+JBD2/CRC16/FS_MBCACHE, the
# module lines below).
